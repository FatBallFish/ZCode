## 执行规则

每个行为适配采用“spec/场景 → 回归先失败 → 最小适配 → 定向验证 → 台账”闭环。这里只指定合同与断言，不预写未经验证的生产实现。不能用实现镜像测试、任意延时或删测试换取通过。

文件名称标为“main新增”时来自固定上游快照，当前custom目录可能不存在。真正开始修改时，以合并后的路径、package.json和architecture-policy为准。文件重命名优先寻找实际目标，不机械创建同名旧模块。

工作树按Codex管理工具规则创建并附着，显式以custom SHA起步；不在原custom目录直接演算实际merge。每个已完成merge形成完整父历史，之后可用小适配提交；未完成merge期间不做普通分领域提交。

## 验证命令表

从候选根目录运行，通过 `mise exec --` 固定工具链。只运行候选package.json实际存在的脚本；出现脚本变化先更新此表及报告。

```sh
mise exec -- node scripts/check-workspace-freshness.mjs
mise exec -- pnpm typecheck
mise exec -- pnpm lint
mise exec -- pnpm architecture:check --changed
mise exec -- pnpm test:unit
mise exec -- pnpm --dir apps/zcode-cli typecheck
mise exec -- pnpm --dir apps/zcode-cli test
mise exec -- pnpm --filter @zcode/relay-server test
mise exec -- pnpm --filter @zcode/mikiko-cloud test
```

合后main提供的schema和architecture测试也运行，并确保pre-push保持二开+上游检查并集：

```sh
mise exec -- pnpm db:schema:check
mise exec -- pnpm test:architecture
mise exec -- pnpm verify:pre-push
```

定向root Vitest测试可用实际存在的文件，例如：

```sh
mise exec -- pnpm exec vitest run packages/services/test/worktreeService.test.ts packages/services/test/sub2apiConfigWriteRace.test.ts packages/services/test/chatgptAccount.test.ts packages/desktop/test/unreadBadge.test.ts
```

以上路径需确认仍被合后Vitest project include覆盖；Node Test或CLI project内测试使用所属包脚本，不能把未收集到测试的exit 0当成功。

定向桌面正式E2E沿已存在runner的 `--spec`（转发为WDIO参数）：

```sh
mise exec -- pnpm --filter @zcode/desktop test:e2e -- --spec ./test/e2e/worktree-long-name.test.ts
mise exec -- pnpm test:e2e:container:conversation
```

新增pending用例使用e2e-case-lifecycle规定的manual-review/capture/replay入口，先确认本机fixture/可用provider；不在方案里捏造新的runner脚本。`test:e2e:all:coverage`可能因真实provider或SSH环境缺失而跳过相关项，必须记录skip及实际命中case；它不自动等价“全环境通过”。

## 输出格式与关闭条件

每个task记录：输入SHA、已改spec、最终文件/owner、测试命令/计数/exit、日志/截图/协议/数据库证据、剩余事项。最终报告分别列accepted-existing、adapted、equivalent、excluded、not-run，不把“代码仍在”写成“功能已保留”。

本计划不要求先承诺工期或额外并行资源。实现按任务顺序推进；发现产品冲突时完成独立工作后提出一个具体决策及推荐方案，不将所有工程选择都变成用户确认问题。
