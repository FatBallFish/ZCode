## 1. 概念与状态空间

| 维度      | 需要区分的等价类                                          | 为什么纳入                     |
| --------- | --------------------------------------------------------- | ------------------------------ |
| 客户端    | desktop主窗、同Host独立会话窗、普通Web、手机远控          | 窗口/平台能力与attachment不同  |
| delivery  | desktop-continuous、web-remote-replayable                 | 一条通过不能证明另一条恢复链   |
| 身份      | 本地、SSH/WSL/Docker，同path不同identity，设备/账号切换   | 防跨Host/跨账号串数据          |
| 对话状态  | 新建空草稿、编辑中、running/queued、终态/历史、权限待处理 | 配置冻结、FIFO、回放与未读不同 |
| 项目/目录 | 正常、多root、无项目、目录缺失、worktree、旧远端单root    | 上游新模型与二开关联最密集     |
| 异常      | 网络取消、迟到响应、半段迁移、进程退出/睡眠、磁盘不足     | 防止错误恢复制造第二份事实     |
| UI        | 明暗、窄屏、中英文、皮肤、完整视图                        | 控件可达与品牌历史修改         |
| 证据      | UI+runtime/protocol/SQLite/files/network/进程             | 不把纯截图作为业务成功         |

## 4. 平台与执行记录

每个落地case记录mode、OS、fixture、候选SHA、action、断言、真实test name、退出码、产物路径和skip原因。上述场景定义不是执行记录，不能批量把planned改为passed。

主机当前为macOS。Windows/Linux原生窗口、混合DPI、WSL、Docker/SSH与手机真机只有实际执行才可勾通过；没有资源时可以继续其他适配，但最终报告必须列明剩余验证。受控relay/provider测试不能替代真实OIDC回调、麦克风授权或签名公证验收。

性能场景单列运行：PERF01同机器至少5次冷启/导航采样；PERF02十万级不作无依据承诺，采用设计明确的10,000任务夹具；PERF03连续20次窗口/guest开关观察资源释放。数值是拟定验收配置，报告填写实际样本和结果。

## 5. Catalog与E2E交接

- 会话相关accepted case回写conversation-session-case-catalog和现有coverage matrix；跨域独立矩阵保留本文件ID，避免同一case多套语义。
- provider/file fixtures按现有case-local目录合同整理；root/shared fixture只放真正通用响应。
- 竞争/迟到结果用受控闸门和事件顺序，不靠固定sleep制造“看起来稳定”。
- 新增E2E先pending/manual review，保存UI与至少一个非UI证据，再按e2e-case-lifecycle晋升；undefined不写成正式断言。
- 迁移/远控/平台故障使用测试副本和隔离设备，不复制真实个人库/凭据到仓库。
