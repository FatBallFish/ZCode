Quick start

  1. Install: grab the installer for your platform from the download page. The Linux AppImage needs chmod +x before running; unsigned macOS builds blocked by Gatekeeper need xattr -cr /Applications/Mikiko.app.
  2. Sign in: follow the onboarding to sign in to your MikikoCC account (or bind a self-hosted Sub2API site under Settings → Mikiko Gateway); API keys and model lists sync automatically.
  3. Pick a model: choose a model and reasoning level from the composer's model selector; capabilities (context window, supported levels) align automatically via smart config and can be overridden in settings.
  4. Start a task: describe what you need, or drop a project folder into the window to create a workspace. The agent reads and writes files, runs commands and reports progress within granted permissions.

Models & providers

The model system has three layers:

  • Account plans: signing in to a MikikoCC / Sub2API site automatically projects a personal provider per API key, with keys, model lists and quotas kept in sync.
  • Custom providers: any OpenAI / Anthropic compatible endpoint, with configurable API format (chat-completions / responses / anthropic-messages), base URL and key.
  • Smart config: recommended capabilities (context window, input formats, reasoning levels and request parameter mappings) match automatically by model ID + API format and keep updating from the Mikiko cloud; fields you edit manually switch to manual management and are never overwritten.

Reasoning levels provide low / medium / high / xhigh / max or a two-state toggle depending on what the model actually supports; the level list and parameter mapping expression are editable per model.

Workflows & automation

  • Dynamic workflows: describe a multi-step flow in natural language on the Workflows tab; the agent orchestrates execution with per-step status in the GUI and you can intervene and adjust midway.
  • Off-peak tasks: built for quota-sensitive heavy jobs (mass refactors, dependency upgrades, routine sweeps). Tasks enter the off-peak queue and run automatically in the scheduled window; both desktop and phone receive result notifications.

Mobile remote control

After signing in on desktop, open the pairing link in a phone browser to attach to the current session: follow task progress, approve file edits and command execution, keep chatting. The realtime link (desktop online) and the replayable recovery link (reconnect after drops) are separate by design, so sessions survive network jitter.

Remote control can be toggled as a whole via a config file; connect and disconnect both give clear, sub-second terminal feedback.

Conversation sharing

Right-click a session → Share, then pick an access mode:

  • Public read-only: anyone with the link can view.
  • Public importable: recipients import locally and continue the conversation (the continuation happens on the importer's machine; the original session is untouched).

The share service runs on self-hosted agent.mikiko.ai; artifacts (documents, images and more) are hosted together with the share and expire automatically after 7 days.

Updates & maintenance

  • Auto updates: on by default; manifests and installers both come from the self-hosted update service (agent-update / agent-dl). Check for updates or switch between the stable / preview channels in settings.
  • Force updates: breaking releases prompt an upgrade via the force-update config so old versions never end up in a broken connection state.
  • Data location: local data lives under ~/.mikiko/v2; Help → Export Logs collects troubleshooting material in one click.

FAQ

  • Model request says "unsupported reasoning level"? The level config disagrees with what the upstream accepts. Edit the model under Settings → Model Providers and set the levels the upstream supports (e.g. low/medium/high), or wait for smart config to hot-update.
  • macOS says "cannot verify developer"? The build is not notarized or signed; run xattr -cr /Applications/Mikiko.app and reopen.
  • Phone remote control cannot connect? Make sure the desktop is online and remote control is enabled; the two sides do not need to be on the same LAN, but both need access to the relay service.
  • Fully offline usage? Model requests go straight to provider endpoints; smart config and update checks fall back to bundled local data when the network is unavailable, so daily usage is unaffected.
